# S4-04 C2 — דוח ביקורת שרת

בוצעה חזרה מקומית של בטיחות אינטגרציה, ללא שינוי קוד production או client,
תלויות, workflows פעילים, כללי משחק או חלון ההוגנות. הענף נשאר
`feature/s4-04-fair-luck`, וה־HEAD נשאר
`733cbb16be508b63ce4fe6a9108923cde9d8ce1b`. ה־index ועץ העבודה היו נקיים בתחילה.
Luck נשאר false כברירת מחדל; החלון הזמני נשאר 60,000 מילישניות.

## מה נבדק

סכמת pre-Luck הופקה מקוד main מקומי מדויק, שנבנה בנפרד ב־target בלי checkout
או שינוי refs. הוכנסו Race אחד, שמונה משתתפים, שמונה שאלות NORMAL פתורות,
שמונה רשומות gameplay עם Energy מגוון עד 100 ושני רישומי Challenge היסטוריים.
החזרה השתמשה ב־MySQL 8.4.11 זמני בלבד: tmpfs, חיבור loopback בפורט 13319,
ומסדים ייעודיים שאינם משמשים DEV או production.

טיוטת המיגרציה מוסיפה עשר עמודות ושתי טבלאות בדיוק, עם BIT(1), ENUM טבעיים,
FK, UNIQUE, אינדקס יורד ואילוצי CHECK בהתאם למיפויים המאושרים. כל העמודות
והשורות המקוריות נשמרו בדיוק, כולל IDs, timestamps ו־Challenge Energy.
ארבעת תוצרי audit התקינים התקבלו; 23 ניסיונות הפרת אילוצים נדחו כמצופה.

startup ו־restart של היישום הנוכחי עם ddl-auto=validate מול המסד המורחב עברו
ונסגרו תקין עם exit code 0. גם מיפויי main הישנים עברו validate מול ההרחבה;
זו ראיית תאימות מצומצמת ולא אישור rollback תפעולי. הבקרה השלילית על בסיס
לא־משודרג ועל התקנה חלקית נכשלה עם exit code 1 וטבלת Luck חסרה, אף שהדגל כבוי.

כשל DDL חלקי מבוקר הוכיח שה־ALTER נשאר לאחר כשל ב־CREATE הבא: סקריפט DDL
אינו טרנזקציה אטומית. ה־preflight זיהה התקנה מלאה וחלקית וסירב להרצה חוזרת.
טרנזקציה סינתטית פתוחה חסמה ALTER; timeout של שנייה החזיר 1205 בלי שינוי סכמה.
לכן אין טענת zero-downtime, ויש צורך בהקפאת כותבים ובנוהל תיקון/שחזור מאושר.

הבדיקות חלקו H2/context בזמן שבדיקות Challenge השאירו שחקנים פעילים; ההשערה
הנתמכת היא קריאות scheduler ל־mock המשותף. לזרימת חיבור SSE אין קריאת presence.
בוצע שינוי test-only של annotation ל־H2 ייעודי למחלקת SSE. כל assertions,
verifyNoInteractions וה־scheduler נשמרו. הלוג וה־XML האדומים נשמרו לצד התוצאות
הסופיות; שינוי זה נוסף ל־patch ואינו שינוי התנהגות production.

ניסיון הפעלה ראשון של שתי בדיקות arbitration על MySQL נכשל ב־setup, לפני
תרחישי המשחק: ה־fixture המשותף דרש את שם מסד ה־Luck למרות שהמסמך מחייב
מסד arbitration נפרד. נוסף hook של אימות מסד בבדיקות בלבד; מסלול Luck נשאר
זהה, ובתת־המחלקה של arbitration נבדקים URL מדויק מורשה, regex מסד ייעודי,
MySQLDialect, מוצר MySQL ובידוד RR. שתי הבדיקות המקוריות ואימותי הבידוד
שלהן נשמרו, ולא שונה הווריפייר של Luck. אחרי התיקון שני התרחישים עברו באמת.
כלומר, שלושה קובצי בדיקה שונו בסך הכול, ללא שינוי Java של production.

המספרים מבוססים על XML חדש לכל ריצה; לוגים, פקודות, משכים וחתימות הקוד נשמרים
בנפרד. במסלול H2 הרגיל הושבתו גם מחלקות MySQL, ולכן יש 65 דילוגים והספירה הכוללת
שונה עקב מקרים פרמטריים שלא נפרסו. אין להחסיר 173 מספירת הריצה המלאה כדי
להמציא את הספירה הזו; XML נפרד ומיפוי המחלקות המדולגות נמצאים בחבילה.
ריצת arbitration היא שתי בדיקות MySQL ישנות ובלתי תלויות, ולא שם אחר
ל־Checkpoint C2 של S4-04. דילוגים מדווחים כדילוגים. אזהרות create/drop,
כשלי rollback מכוונים והיסטוריית כלי העזר נשמרו. לא בוצע hosted CI.

## CI ותקציב חיבורים

הוכנה טיוטת workflow בלתי מוחלת: H2 רגיל, MySQL ייעודי ל־Luck ובדיקה נפרדת
ל־arbitration הישן, עם Java 21, wrapper, timeouts ושמירת ראיות. parsing של YAML
ובדיקות תחביר Bash עברו; Linux/GitHub Actions עצמם לא הורצו. מוצעות שתי חלופות
תכנון, עם המלצה להתחיל ב־workflow מינימלי; אימוץ ו־action SHA pins דורשים ביקורת.

נמדדו W=10 ו־writer timeout של 30 שניות ב־startup המקומי. Reader ברירת מחדל R=2,
זמן רכישה 2,000ms וזמן שאילתה 2s. עבור N מופעים נדרש N*(W+R)<=B וגם
B+reserved<=max_connections. תקרת המעבדה היא 151 בלבד; אין הסקה על sizing לייצור
ממספר החיבורים של Spring test contexts או מתוצאות זמני הבדיקות.

בחבילה. החזרה הניתנת לשחזור מחייבת משאבים זמניים וניקוי שלהם.

נעצר לביקורת דיאנה. החלטה נפרדת נדרשת על מדיניות המיגרציה ועל תוצרי C2 לפני

## ראיות MySQL סופיות

בכל אחת מהריצות המלאה והממוקדת עברו 173 בדיקות Luck ב־MySQL אמיתי. שתי בדיקות arbitration עברו בנפרד, ואינן חלק מ־173 אלה. בכל ריצת Luck נשמרו 280 מדידות תשובה, עשר חזרות לכל קבוצת 2/4/8 משתתפים באותו מרוץ ובמרוצים שונים. אלה מדידות service/JPA, לא HTTP או SLA.

מדדי הסיום: deadlocks=0, InnoDB lock_timeouts=0 ושגיאות תקרת חיבורים=0. שיא החיבורים הוא 110 מתוך 151 במעבדה, כולל Spring test contexts ופרובים; אין להסיק ממנו sizing לפריסה. timeout המטא־נתונים המכוון הוא בקרה נפרדת.


## זמינות ראיות היסטוריות

ארכיון ה־ZIP המקורי המאושר של C1 לא נמצא מקומית בזמן האריזה. אין טענה לשחזורו
או לאימות 493 רשומותיו. בדיקות C1 עצמן מחדשות פלטים ב־target/c1-evidence;
הפלטים החדשים של C2 נשמרו בנפרד עם שיוך לריצה. זהות קוד C1 אומתה בנפרד
מ־run metadata שנשמר: כל 526 חתימות Java בתחילת C2 תואמות ל־C1 המאושר.
אם הארכיון המקורי זמין אצל הביקורת, יש לשמרו כהיסטוריה; חבילת C2 אינה תחליף לו.
